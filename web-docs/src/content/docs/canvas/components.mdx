## The Components page

Every project keeps its mains on a page named **Components**, made the first time you need it. Create a component with `⌥⌘K` and the main moves there, in a frame of its own sized to it; what stays where you made it is an instance linked to that main. A URL or code import puts its mains there too, one frame per component or variant set, laid out in a grid, instead of one large frame beside the page.

On the Components page a variant set has a dashed purple outline and a **+** just below it: click it to add a variant, and the frame widens to show it. Edit a main there and every instance on every page follows, at the same size.

Imports made before this change keep their Components frame and keep working.

- **MCP / API:** `home_components` with a `frameId` moves the mains of that frame to the Components page, the same as the app does after `⌥⌘K`.

## Go to main component

Select an instance and click the target icon in the Instance inspector header, or right-click it and pick **Go to main component**. Feega switches canvas if the main lives on another one, pans to it and selects it. Hover the icon to see where the main is (`canvas › frame`). In the Components panel, the same icon on a tile is **Show main**.

## Instances follow their main everywhere

Every instance depends on its main, in any frame and on any canvas of the project. Edit the main and every instance shows the change, keeping its own overrides; open canvases update on their own. Delete the main, or the frame that holds it, and its instances detach: they keep the look they last had.

## Components across canvases

The **Components** panel in the rail (`Alt+5`) shows the components of every canvas in the project as a grid of tiles, grouped by canvas. Each tile is a live preview of the component itself, cropped to what it draws on a light or dark tile that keeps it visible, with its name underneath; a variant gets its own tile. Previews redraw when the main changes. Search by component or canvas name. Drag a tile onto the canvas to add an instance, or hover it for **Show main** and **Copy**. The list response carries each frame's `revision`.

- **Drag** a component onto a frame of the current canvas to add an instance at the drop point. The frame under the pointer is highlighted while you drag; the main is copied into that frame.
- **Drop on empty canvas** to place the instance as a free element at the drop point.
- **Copy** with the copy button or `⌘C` on a row, then paste with `⌘V` over a frame, or with a frame selected.
- **CLI:** `feega components <projectId>`. **MCP:** `list_project_components`. **API:** `GET /api/v1/projects/{projectId}/components`, and `GET /api/v1/projects/{projectId}/components/{frameId}/{compId}` for one main.

## Variants

A component can have several variant properties, like Size (S, M, L) and State (default, hover). Select an instance and the variant matrix appears in Properties: one cell per combination, the current one highlighted.

<DemoVideo name="variant-matrix" caption="Switch an instance across a Size by State matrix, then add a property." />

1. Select an instance of the component.
2. Click a cell in the matrix to switch the instance to that combination. Overrides on the instance stay.
3. To add a property, type its name (`Tone`) and values (`Light, Dark`) under the matrix and press Add property. Feega creates a variant for every missing combination, up to 64 per set.
4. A dash marks a combination that does not exist; it cannot be picked.

The dropdown per property and the Swap list still work for switching one axis, or swapping to any other component.

**Agent and CLI.** The `component` tool covers the same steps:

```json
{ "action": "define-variant", "comp": "<main id>", "prop": "Size", "values": ["S", "M", "L"] }
{ "action": "set-variant", "clip_id": "<instance id>", "variant": { "Size": "L", "State": "hover" } }
```

Through the CLI: `feega motion ask <nodeId> "Give the Buy button Size S, M, L and State default, hover, then set the cart button to L hover"`.

## Properties

A component can expose properties: show or hide a layer, edit text, swap a nested component, or surface a nested component property. Set them per instance.

### Preferred swaps

An instance-swap property can list preferred components. Under the instance, tick the components to prefer in Preferred; the swap dropdown then shows them first, under Preferred, above All components. Preferred is a suggestion: any component can still be swapped in.

Agent: `set-preferred` with `comp`, `prop` (the swap property) and `preferred` (main component ids).

## Overrides

Instances can override fill, stroke, image, visibility and effects, each with its own reset. Double-click into an instance to move or restyle its elements; only that instance changes and the main stays as it is.

| Action | Where |
|---|---|
| Create component (`⌥⌘K`) | Right-click menu, Design right bar, command palette (`⌘K`) |
| Detach instance | Right-click menu, Design right bar, command palette |
| Reset all overrides | Right-click menu, Design right bar, command palette |
| Push overrides to main | Right-click menu, Design right bar, command palette; every copy follows |
