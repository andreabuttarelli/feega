Paste the address of a public web page and Feega draws it as a frame you can edit: text stays text in the page's own fonts, the page is rebuilt as stacks (see below), backgrounds, gradients, borders, corners, shadows and blurs become fills, strokes and effects, pictures are copied into your project, SVG icons and logos become vector paths. It is not a screenshot: only what a frame cannot hold as layers (a video, a canvas, an embedded page, a masked or blended block) comes in as a picture of itself.

## In the app

Open the insert menu (**+**), go to **Import**, choose **From URL…**, paste the address and press **Import**. The frame lands in the middle of the view, named after the page title.

## What the import does before reading

The page is scrolled to the bottom and back so lazy pictures load and scroll-revealed blocks show; running animations are finished, videos are stopped on their last frame, and cookie banners are hidden.

## Stacks

The imported frame is laid out like a well-built Figma file. The page is a vertical stack of sections; inside, blocks one under the other become vertical stacks, columns side by side become horizontal stacks, a grid becomes rows, and the lines of a paragraph become one text layer. Gaps and paddings come from the page and bind to its spacing variables.

Only what really overlaps stays absolute: decorations behind or above the content, overlays like a cookie banner, glyph-by-glyph counters, and anything inside a block that clips an overflowing child. Every layer lands where the page drew it.

Only layers that do something are kept. A wrapper that draws nothing and holds one layer is removed and its padding moves to the stack around it, so a button holds its label directly; empty layers go; nested stacks running the same way merge. Layers are named by role or content (Nav, Logo, Button, Icon, the label's text), never by HTML tag. Wrappers that clip, and anything inside a component, stay when removing them would change how the page looks or break the link to the main component.

Make the page stack narrower or wider (select the stack under the frame, change W) and sections fill the new width, full-width rows stretch, and wide rows spread their items. Text keeps the size and line breaks it had in the page.

## Fonts

Web fonts the page loads are copied into your workspace's uploaded fonts and used by the frame, so text wraps where it wraps on the page. Text set in system fonts uses the closest free face (Inter for the system UI font, Arimo for Helvetica and Arial, Tinos for Times, Gelasio for Georgia, JetBrains Mono for monospace).

## Limits

- Public `http`/`https` pages only. Private network addresses and pages behind a login are refused.
- The page is read at desktop width (1280 px), down to 65 536 px from the top, up to 10 000 layers. A page taller than 16 384 px comes in as frames stacked one under the other.
- Four imports a minute per person.
- Not yet: tablet and phone layouts as breakpoints.

## Design tokens

Colours become variables in a collection named after the site (`Stripe/Primary`), type, shadows and gradients become styles (`Stripe Body`), and the layers that use them are bound. **Primary** is the fill of the page's main buttons, picked by how much they stand out from the page; when no button is coloured, the brand colour of the site wins if the page uses it. Other colours are named by role (Background, Text, Surface, Border, Accent), then by lightness (`Navy`, `Ink` for very dark tints, `Tint` for very light ones), by hue (`Green`) or by what they paint (`Surface 2`). The page's `h1` style is **H1**. Text colours, fills, single solid borders and plain rounded corners are bound; a corner radius is a number variable in px (`Radius M`), so changing it re-rounds every layer bound to it.

Starting from a website on `/start` makes the brand first, so the first import already follows its palette.

## Components

Blocks the page repeats (cards, logos, buttons, list items) become one main component and linked instances. Each instance keeps its own text, pictures and colours as overrides, so editing the main updates every copy and **Reset** brings one back to the main. An instance colour that matches the main's token is not kept as an override, so it stays bound to the variable. Blocks with the same structure but a different background, border or shadow become variants of one component (`Style=Primary`, `Style=Secondary`); buttons and links of up to three heights also get `Size=Small`/`Medium`/`Large`. Names come from what the block is: button, card, feature card, nav link, logo. Painted buttons and links that share a structure become one Button set even when each style appears once (a purple and a white call to action), and logos with different marks are variants (`Variant=1`, `Variant=2`) of one Logo set.

Each main has properties: its texts, nested ones included (`Label` on a button, `Title` and `Text` on a card) and toggles to show or hide its icon or picture. Buttons and links whose background is a colour variable get `State=Default`, `Hover` and `Pressed` variants, bound to `Primary hover` and `Primary pressed` (a shade of the same colour, always far enough from it to see), so changing Primary restyles every state.

All mains also sit on a **Components** frame next to the imported page, packed in a compact grid and grouped by component; that frame is their home, so editing a main there updates the page. They are listed once in the **Components** panel, under the frame that owns them.

A block is turned into a component when it repeats at least twice, is at least 16 px on each side and has a background, a picture or an icon. Sidebar rows, nav links and buttons inside auto layout rows count too. Copies with a different icon or spacing stay linked: the difference is an override on that instance, as in Figma.

## CLI

```bash
feega canvas import-url $PROJECT https://example.com --canvas <canvas> --x 0 --y 0
```

`x` and `y` are the canvas position of the frame centre. The answer has `frame_id` and `truncated` (true when the page hit the layer or height cap).

## MCP and API

Over MCP: `canvas_tool({ project_id, op: "import_url", input: { canvasId, url, x, y } })`.

Over HTTP: `POST /api/v1/projects/{projectId}/url-import` with `{ canvasId, url, x, y }`. Errors: `not_public` (400), `failed` (502, the page answered with an error), `unreadable` (422), `rate_limited` (429), `no_browser` (503).
