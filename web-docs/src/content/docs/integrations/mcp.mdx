feega's MCP server lets an agent read and write your canvases with the same sign-in as the CLI. There are no static API tokens.

- Remote: `https://mcp.feega.app/mcp`, Streamable HTTP. The host must send `Authorization: Bearer <access token>`; discovery is at `/.well-known/oauth-protected-resource`. A missing Bearer is a `401`, not a broken server. Health: `https://mcp.feega.app/health`.
- Local stdio: `feega-mcp` (`cli/mcp/stdio.ts`), sharing the session file `~/.config/feega/session.json`.
- Local mode: `npx feega mcp`, stdio against the `npx feega` canvas on your machine. See [Local MCP](#local-mcp).

In the canvas, **Connect** next to the project name shows these setups with copy buttons: the remote ones in the cloud, the local ones (with the right port) in local mode.

## Claude Code

```bash
claude mcp add --transport http feega https://mcp.feega.app/mcp
```

**Unverified:** the OAuth round in Claude Code against feega's authorization server was not run for these docs. If it fails, use the local option below.

## Claude (web and desktop)

Customize → Connectors → **+ Add** → custom connector. Name it `feega`, paste `https://mcp.feega.app/mcp`, then sign in. Custom connectors need a paid Claude plan.

## Codex

```toml
# ~/.codex/config.toml
[mcp_servers.feega]
url = "https://mcp.feega.app/mcp"
```

Then `codex mcp login feega`.

## Local MCP

Local mode (`npx feega`) has no account and does not reach the remote server: the remote one reads your cloud canvases, not the `.feega` file on your machine. Connect agents to the local server with `npx feega mcp`, a stdio server that talks to the running local canvas. It needs no login.

`--port` is the port the local canvas runs on (default `5173`); `npx feega` prints it (`feega: open http://127.0.0.1:<port>`), and **Connect** in the canvas fills it in.

```bash
# Claude Code
claude mcp add feega-local -- npx -y feega mcp --port 5173
```

```toml
# Codex: ~/.codex/config.toml
[mcp_servers.feega-local]
command = "npx"
args = ["-y", "feega", "mcp", "--port", "5173"]
```

```json
// Cursor: ~/.cursor/mcp.json — Claude Desktop: claude_desktop_config.json
{ "mcpServers": { "feega-local": { "command": "npx", "args": ["-y", "feega", "mcp", "--port", "5173"] } } }
```

The first run downloads the same app bundle `npx feega` uses. Keep the local canvas running: the MCP server only forwards to it.

## Local stdio from a clone (Cursor, Claude Desktop, any client)

Sign in once with `feega login`, then add:

```json
{
  "mcpServers": {
    "feega": {
      "command": "bun",
      "args": ["run", "/ABS/PATH/to/feega/cli/mcp/stdio.ts"]
    }
  }
}
```

Needs [Bun](https://bun.sh) and a clone of the repo (or the CLI binary). Then call `query` on `projects` to confirm you are signed in.

## Cursor with the remote URL

```json
{ "mcpServers": { "feega": { "url": "https://mcp.feega.app/mcp" } } }
```

Cursor's `cursor://anysphere.cursor-mcp/oauth/callback` is accepted by feega's registration endpoint. If sign-in still fails, bridge with [mcp-remote](https://www.npmjs.com/package/mcp-remote).

## First calls

1. `query` on `projects`.
2. `describe` with `{}` to see every tool and op; `find_tools` to search them.
3. `load_tools` to list the ones you need, or run any through `edit` `{op, input}`.

A session lists 10 core tools (`query`, `view`, `edit`, `describe`, `render_video`, `get_render`, `list_orgs`, `find_tools`, `load_tools`, `unload_tools`; about 900 tokens); the rest load on demand. Claude Code refreshes on `tools/list_changed`; Cursor does not, so call loaded tools by name.

The whole surface: [MCP tools](/reference/generated/mcp-tools/) and [Edit ops](/reference/generated/edit-ops/). Never guess an org or project id: read it with `query` first.

## Know what "this" means: get_selection

<DemoVideo name="get-selection" caption="Select two nodes in the app, then ask the CLI what is selected." />

An agent that is told "make this darker" needs to know which node "this" is. `get_selection` reads it from the canvas you have open.

1. Open the canvas in feega and select one or more nodes (click, `Shift`-click or drag a box).
2. Call the op with the canvas id: from the CLI, `feega canvas $PROJECT get_selection --input '{"canvasId":"<canvas>"}'`; over MCP, `canvas_tool({ project_id, op: "get_selection", input: { canvasId } })`.
3. The answer lists one entry per open session of yours: `sessionId`, `selection` (the node ids), `view` (centre and zoom of the viewport) and `at`.

```json
{ "sessions": [{ "sessionId": "d6e8e2c8-...", "selection": ["4e17c983-...", "e75cf9d6-..."], "view": { "cx": 878, "cy": 229.9, "zoom": 0.61 }, "at": 1793042000000 }] }
```

With no tab open on that canvas the answer is `reason: "no_open_session"`. Only your own selection is returned, nothing is stored, and the call waits up to 3.5 seconds for the app to report it.
