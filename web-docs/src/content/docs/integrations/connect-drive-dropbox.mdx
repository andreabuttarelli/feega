Google Drive, Dropbox and OneDrive are the three cloud providers. Each person connects their own account, and files never move without a click.

## Connect

From the picker, or from Settings, Profile, Connections.

1. On the canvas, open **+** in the bottom bar.
2. Under **Import**, choose **Import from the cloud**.
3. Pick the **Google Drive**, **Dropbox** or **OneDrive** tab and choose **Connect**.
4. Sign in with the provider and approve access. You land back on the canvas with the picker ready.

The sign-in runs through Composio: Feega never stores a password or a provider token, and every call to the provider goes through the connection you approved.

## Import

1. Open the picker as above and choose the provider tab.
2. Open folders with a click. The path at the top goes back up.
3. Choose a file. It lands on the canvas at the middle of your view, as an image, video or document node, and is selected.

Folders list 200 entries at a time; choose **Load more** for the next page. Google Docs, Sheets and Slides import as PDF, and Drawings as PNG. Other Google formats, such as Forms, show as not importable.

## Export

1. Select one image or video node.
2. In the selection bar, open the cloud menu and choose the provider.
3. Open the destination folder and choose **Export here**. Leaving the picker at the top exports to the root (My Drive, Dropbox home, OneDrive Files).

The file keeps the name it was uploaded with. Dropbox renames on a clash, so nothing is overwritten.

## Disconnect

Choose **Disconnect** in the picker, or in Settings, Profile, Connections. Feega forgets the connection; the next import or export asks you to connect again.

## Troubleshooting

| What you see | Why | Fix |
| --- | --- | --- |
| "Connect Google Drive to continue." | No connection, or it was revoked | Choose **Connect** |
| "Connections are not set up on this server." | Self-hosted without `COMPOSIO_API_KEY` | See [Self-hosting](/self-hosting/) |
| "Could not load files." | The provider refused the listing | Reconnect, then retry |
| "The provider would not let Feega download that file…" | The provider refused the download | Check you can open the file in the provider |
| "The provider refused the upload…" | The provider refused the upload | Pick a different folder |
| "feega could not read the file to export" | The asset could not be read | Try again |
| The cloud icon is missing | Local mode hides cloud controls | Use the hosted app |

## CLI, MCP and API

The CLI has `feega cloud status|files|import|export|disconnect <projectId> ...`, and MCP has the `cloud` tool with the same actions. Connecting is a browser sign-in in the app.

The REST endpoints, all under `/api/v1/projects/{projectId}/cloud` with `provider` set to `google_drive`, `dropbox` or `one_drive`:

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/` | Which providers are connected and set up |
| `POST` | `/{provider}/connect` | `{ returnTo? }`; answers the Connect Link `{ url }` |
| `GET` | `/{provider}/files?folder=&cursor=` | List a folder: `{ entries, next }` |
| `POST` | `/{provider}/import` | `{ fileId, place: { canvasId, x, y } }` |
| `POST` | `/{provider}/export` | `{ assetId, folder, name? }` |
| `DELETE` | `/{provider}` | Disconnect |

They answer `409` with `not_connected`, and `501` with `not_configured`.
