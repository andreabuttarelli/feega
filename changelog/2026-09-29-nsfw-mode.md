# Separate NSFW mode

Wiro models (uncensored and not) left the general canvas: they exist only inside NSFW projects,
a separate space with its own entry, access and isolation. Before, an org-level opt-in made
uncensored models appear in every project of that org.

- Schema (`20260929230000_nsfw_mode.sql`, applied): `projects.mode` enum `standard|nsfw`,
  default standard, immutable by trigger. `user_age_verifications` (user, provider, method,
  result `adult` only, no documents; no write policy — only the verifier writes, via a declared
  service-role use). `feature_flags` (`nsfw_mode`, off). `billing_scopes` table referenced by
  `ai_calls.billing_scope` / `credit_ledger.billing_scope`, filled by triggers from the project
  (ledger from its `ai_call_id`). `assets.nsfw` set by trigger from the project. Triggers refuse
  a canvas share token, a node public link and a `post_sources` row in an NSFW project.
- Rules in one place: `src/lib/project-mode.ts` — what each mode allows (share, publish,
  schedule, promote, catalogue writes, Wiro/standard models), refusal codes, moderation profile
  by mode × model, storage folder by mode, catalogue filtering.
- Access: `src/lib/nsfw-access.ts` — the lock is the first failing row of plan → org opt-in →
  flag+verifier ("coming soon") → user age. Section hidden when plan/opt-in fail.
- Age verification is a port (`src/lib/server/nsfw/age-verification.ts`). Only adapter:
  `manual_admin`, active only when `dev` and `NSFW_DEV_MANUAL_VERIFICATION=true` (that env also
  stands in for the flag in dev). In production nothing is configured, so NSFW stays "coming
  soon".
- Wiring: project switcher (`CanvasTopBar.svelte`) → `/p/[projectId]/nsfw` (load/verify/create)
  → `nsfw-workspace.ts` → `projects` (mode nsfw) + first canvas. Layout lists NSFW projects in
  their own section only for open users, badges and borders the shell, 404s a locked NSFW
  project; `enterApp` never lands on one.
- Generation: `runGenNode` → `generationRefusal` refuses Wiro in standard projects and any run
  in an NSFW project whose user is locked. Wiro screening uses the profile table; outputs land
  under `<userId>/nsfw/wiro/`.
- Isolation: canvas actions share/share_canvas/create_post/plan_post/schedule_post/
  calendar_posts go through `scopeAllowing`; `/s/[token]` returns not found; deliveries refuse
  NSFW assets; `hooks.server.ts` refuses calendar, promote, ads, influencers sections in an NSFW
  project; MCP `query`/`rows` exclude NSFW projects/canvases/nodes (`hidden-scope.ts`) for locked
  users; project agent endpoints use `findReachableProject`.
- AI-generated label on every generation output and `-ai-generated` in the downloaded file name.
- Not done: embedded file metadata (C2PA/XMP); non-Wiro generators in NSFW projects are flagged
  (`assets.nsfw`) but stored under the standard folder.
