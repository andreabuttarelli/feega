# Organization fonts get a table, an org-level API and reach code frames

**Before.** Uploaded fonts were `assets` rows (`type = document`, `mime_type font/*`) with the
face (`family`, `weight`, `italic`) as JSON in `content`. Only the frame editor could upload,
list, rename and delete them, through page actions bound to a motion node. Code frames never saw
them, the font picker listed them without their face, and local mode dropped any font no frame
referenced when it saved the `.feega` file.

**Now.**

- `org_fonts` (`id`, `org_id`, `family`, `weight`, `style`, `path`, `uploaded_by`, `created_at`),
  RLS on `auth_org_ids()` for reads and `auth_editor_org_ids()` for writes. `id` is the asset id
  (`references assets(id) on delete cascade`): frame documents keep pointing at `variants[].assetId`
  and the render pipeline keeps signing the asset. Several rows with one `family` are one family.
  The migration backfills existing font assets.
- Brand fonts (branch `feat/brands-panel`) should reference `org_fonts.id`, not upload again.
- `font-upload.ts` lists, renames and deletes through `org_fonts`; `storeFontFile` validates the
  bytes it already holds (size cap, magic-number sniffing, family read from the name table and
  sanitised) before storing under `${orgId}/fonts/` in `canvas-assets`.
- `/api/v1/org/fonts` (`GET` with signed urls, `POST` multipart, `DELETE ?family=`),
  `feega fonts [upload|delete]`, MCP `org_fonts`.
- Code frames inject `@font-face` for every org font (`orgFontCss`); the font picker previews
  uploaded families in their face; Settings → Fonts manages them.
- Local mode keeps every font asset in the `.feega` file and rebuilds `org_fonts` from them on open.

**Kept.** `assets.content` still carries the face JSON: the motion agent's asset labels and the
local `.feega` file read it. Rename writes both.

**Discarded.** Moving font files out of `assets`: every render path signs fonts as assets, and
the motion documents reference asset ids.
