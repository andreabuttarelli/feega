# Frame branches, step 4: the editor UI

The frame editor bar has a Branches button next to version history
(`BranchesMenu.svelte`). On a frame it lists its branches and creates one
by name (saving first), then opens it. On a branch it shows what it was
forked from, "Review and merge" — one row per conflict with the frame's and
the branch's value and a choice, default the frame — "Merge into the frame"
and "Drop this branch". Merge and drop return to the frame.

Branch switches use a full page load: the editor's state (history, base
revision, presence) is per node, and reusing the component across nodes
kept the first node's state. New page actions: `branches`, `createBranch`,
`reviewBranch`, `mergeBranch`, `dropBranch`; inputs are parsed with the
editor op schemas.

Two-browser e2e (`frame-branches.spec.ts`): branch, change opacity on the
branch, a second browser changes it on the frame, review shows one
conflict, keep the branch, merge — the frame's head has the branch value
and the branch node is soft-deleted and absent from the canvas.
