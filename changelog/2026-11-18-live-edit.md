# Direct editing on live frames (local Feega)

Click an element of the running app inside a selected live frame, change text, colour, font
size/weight, padding, margin, gap or radius, and the one class or text is rewritten in its
source file.

Path: `LiveFrameNode.svelte` overlay → `feega:inspect` to the page bridge
(`packages/source-map`) → `live-selection` → `LiveInspector.svelte` → `editLive`
(`live-edit-client.ts`: preview in the page first, then write) →
`POST /api/v1/local/live-edit` → `liveEdit` (`src/lib/server/live-edit/`) → `livePatch`
writes the file in the live checkout and commits on `feega/live`. Undo is a `FrameStep` on
the canvas undo stack that reverts the commit. `feega live-edit|live-undo|live-changes|
live-push`, MCP `live_edit`.

Decisions:

- **Where the write lands.** The rule was "local Feega writes on a `feega/` branch and never
  touches the working copy". So the preview must run from that branch: `devFolder` now
  returns a git worktree of `feega/live`, and the dev server is started there. Cost: work not
  committed is not in the live frames, and a dev server the user already runs in their own
  folder is no longer reused.
- **Not under `.git/`.** The first version put the worktree in `.git/feega/live` with
  `node_modules` symlinked. Vite denies `**/.git/**` and SvelteKit's entry resolved to the
  real `node_modules` outside the served root: both 403, the page never hydrated. The
  checkout now lives in `~/.feega/live/<repo>-<hash>` (`FEEGA_LIVE_DIR`) with its own
  `node_modules`, copied with `COPYFILE_FICLONE`. It is not refreshed when dependencies
  change: delete the folder to rebuild it.
- **Bridge without `index.html`.** `transformIndexHtml` never runs in SvelteKit, so the
  bridge was never loaded there. The plugin now appends the bridge import to Vite's client
  module, which every Vite dev page loads, and adds its folder to `server.fs.allow`.
- **One write at a time.** Two edits fired together failed on `index.lock`; writes are
  queued per checkout.
- **Tokens follow the page's rem.** The bridge reports the root font size; a page at 19px
  turned "16" into `py-4` (19px). Scales are computed from rem, and a value off the scale is
  written as an arbitrary value.
- Only the owned class is swapped (`CLASS_RULE` in `live-fields.ts`), never the whole list.

Limits: variant classes (`sm:`, `hover:`) are not targeted; non-literal class expressions are
refused; the picked outline can lag one hot reload behind; the frame label still reads
"Code frame"; `feega live-edit` assumes a 16px rem unless given a token.

Verified on a fresh clone of traidue (SvelteKit, Tailwind 4): title text of `/chi-siamo`
(written to `messages/it.json`), its colour, padding of the intro paragraph, undo; the
clone's working copy stayed untouched.
