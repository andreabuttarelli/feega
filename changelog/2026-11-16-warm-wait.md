# The canvas sleeps while it waits to warm tiles

For 500 ms after every edit or camera move the core reports `warming` (tiles warm only once
the canvas has been still for `WARM_AFTER_MS`). `paintOn` treated that as "paint again next
frame", so the paint loop spun every rAF just to wait — on the user canvas copy that was
~10 ms of main thread per 250 ms with nothing on screen changing, and a saturated main
thread at 4× CPU.

The core now also reports `warm_wait` (ms left before warming is due). `paintAgain` decides
the next step from one table: pending work, zoom, overlay or scene → next frame; only waiting
to warm → a timer for the time left; otherwise stop.

The edit bench gained switches to measure real main-thread cost: `BUDGET_VSYNC=1` keeps the
frame-rate cap (the default uncapped flags made the spin cost ~130 ms per edit and hid
everything else), `BUDGET_PIXELS=0` drops the pixel probe (its readback was the second biggest
cost), and `edit-busy-<target>.json` records CDP task time input→patch, over the edit cycle,
and over an equal idle window.
