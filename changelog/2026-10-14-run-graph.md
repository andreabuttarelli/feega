# Run downstream, run stale, runs panel

"Run flow" needed a hand-picked, connected selection of two or more nodes. Changing an upstream
prompt left every result below it silently out of date, with no way to see or redo them at once.

`$lib/canvas/run-graph.ts` plans two graphs in pure code. **Downstream**: the node and everything
it feeds, walking through nodes that do not generate (a doc between two generators is skipped,
not a break). **Stale**: a generated result whose latest success is older than an upstream
result's, or whose input is stale itself; a node that never ran is new, not stale. Both reduce to
the nearest runnable ancestors as dependencies; a cycle is refused. Queueing reuses the workflow
tickets (`enqueueSteps`, split out of `enqueueWorkflow`): the tick runs each step after its
inputs and blocks what depends on a failure.

Entry points: toolbar "Run from here" and "Re-run out of date" (`selection-actions.ts` gates, now
a table), a canvas "Run all out of date (n)" button and a runs panel (latest 20 runs: node,
status, cost) — all quote steps and credits before queueing (`graph_plan` → `run_graph`). Chat,
API, CLI and MCP get `preview_run_graph` / `run_graph` as rows of the canvas op table.

Staleness compares run timestamps only: an edited prompt on a doc node has no output time, so it
does not mark its dependents. The Playwright run on a 3-node chain was not run (production
Supabase is off limits for seeded e2e); the same path is covered by a route test on the real
actions and an integration test that queues and drains the chain with a fake engine.
