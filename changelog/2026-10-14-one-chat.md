# One chat for the canvas and its frames

The user talked to the canvas chat, then to a second AI inside each frame, with its own thread.
Now the editor's Chat tab is the canvas chat: same thread, same session as the sidebar.

The canvas chat edits frames itself through `frame_tool`, which calls `runMotionTool` — the
runner MCP `motion_tool` already uses — so validation, moderation and revisions are shared, and
no tool is defined twice. It reaches the 150 editor tools by name (`list_frame_tools`,
`describe_frame_tool`): 1,151 chars of prompt instead of 136,557. The editor sends the open frame
(id, selection, playhead, still/video) as context; `view_frames` is drawn by the open editor
through the existing frames upload, else the server browser, else refused.

Whole-video work still goes to the motion agent (`ask_motion_agent`) for its gates, roles and
critic. Old frame threads are shown read-only above the editor chat. Decision and discarded
options: `docs/adr/0007-one-chat-drives-canvas-and-frames.md`.
