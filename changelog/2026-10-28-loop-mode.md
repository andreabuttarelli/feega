# Loop mode on the canvas timeline

Before: the canvas timeline (`FrameTimeline`) advanced with `Math.round(frame + ms·fps/1000)`
per paint, so a 30 fps doc played at 2x on a 60 Hz screen and froze on 120 Hz; it always
looped the whole doc, ignoring `doc.workArea` (`loopFrame` existed, unused) and
`interactive.loop`; `I/O/B/N` and "Clear work area" had no handler on the canvas, so the
work area could only be set by the agent.

Now: `advance` keeps a fractional head and wraps inside `loopRange(doc)` or stops
(`Wrap.Stop`) when looping is off. Transport gets a loop toggle (writes
`interactive.loop`, the same flag the embed honours), a "Make seamless" button
(`closeLoop`: closing key at the loop end with the first key value, keys past it dropped)
and a clear button; the ruler's work-area bar is always shown with draggable in/out
handles. Agent: new `close_loop` tool; parity rows for `Tool.Loop` / `Tool.CloseLoop`.

Discarded: a separate "preview loop" flag distinct from `interactive.loop` — two loop
switches would disagree.
