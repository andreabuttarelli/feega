# `npx feega`: local mode in one command

**Before.** Local mode needed a clone, `npm install` and a multi-minute build (`npm run local`).

**Now.** `npx feega [file.feega]` (package in `npx/`) checks the newest `app-v*` GitHub release
(2 s timeout) on every start, downloads that bundle into `~/.feega/app/<version>/` if missing,
runs `npm ci --omit=dev` there, then starts the bundled `scripts/local.mjs` on 5173 (`--port`,
`--no-open`) and opens the browser. Offline it starts the newest cached version. The file
resolves against the caller's cwd.

- Bundle (`npm run app:bundle`): `build/`, `local.mjs`, `node-server.mjs`, a trimmed
  `package.json` and its lockfile. No `node_modules`: native deps (sharp…) installed on Linux would
  break on macOS/Windows, so the user's machine installs them.
- A `.complete` marker makes an interrupted download redo itself.
- `FEEGA_APP_BUNDLE=<path|url>` uses a local bundle, cached as `~/.feega/app/local`: test without
  publishing.
- Release: every push to `main` runs `.github/workflows/app-release.yml`. The version lives only in
  `app-v*` tags: newest tag, patch +1 (`npx/package.json` seeds the first, 0.1.0). It creates the
  release with `feega-app.tar.gz`, then publishes `feega` to npm. No commit back to main; a rerun
  on the same commit reuses its tag and skips what already landed.
- `typescript` moved to `dependencies`: adapter-node inlined it from devDependencies and its
  `__filename` crashed the node build at startup (`npm run local` was broken too).

Discarded: a bundle with no dependencies (adapter-node externalises them; native modules can't be
inlined); a version committed to main (commit loop).
