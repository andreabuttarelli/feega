# Perf: the engine wasm compiles in parallel and caches for a year

Before, `warmCore` imported `gpu_core.js` and only then did its init fetch `gpu_core_bg.wasm`: two
round trips in series, and both URLs were plain paths served `max-age=0, must-revalidate`, so
every open revalidated 1 MB of wasm.

Now `npm run build:gpu-core` writes `CORE_VERSION` (sha256 of the shipped wasm + glue, 12 chars)
into `packages/motion-core/src/motion/gpu-full/core-version.ts`. `core-web.ts` loads
`/gpu-core/gpu_core.js?v=<version>` and, at the same time, `WebAssembly.compileStreaming` on
`/gpu-core/gpu_core_bg.wasm?v=<version>`, then hands the compiled module to the glue's init.
`vercel.json` serves `/gpu-core/*` with a `v` query as `immutable, max-age=31536000`; the
unversioned paths (interactive export, scripts) keep the old caching.

`scripts/gpu-core-version.test.ts` fails when the shipped wasm changes without the version: any
PR that rebuilds the engine must run `npm run build:gpu-core`, not `cargo build` by hand.

Discarded: renaming the files with the hash (every other reader of `/gpu-core/` would need the
manifest); a `<link rel=preload>` (the load already starts in the route's `load`).

Measured on the landings fixture, localhost, 5 cold opens each (median ms from navigation):
`wasm-asked → wasm-ready` 261 → 54, `gpu-ready` 532 → 409, `first-drawn` 536 → 481.
Brotli: Vercel compresses `application/wasm` itself; adapter-node precompresses `.br`.
