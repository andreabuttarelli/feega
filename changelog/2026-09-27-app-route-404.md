# `/app` no longer 404s: it redirects to the current home

`/app` was the dashboard before the canvas-first shell (`/p/[projectId]`) replaced it. Nothing
in the code built a new `/app` UI after that move, but every entry point — the root hook, login,
OAuth callback, password reset — still redirected there by name, and in production the deployed
build's route manifest did not include `/app` at all: visiting it, or landing on `/` (which
redirected to it), served SvelteKit's generic 404.

## What changed

- `homePathFor(db, deps, user, orgId)` in `$lib/server/tenancy/entry.ts` is the one place that
  decides where a signed-in user lands: it runs the same idempotent bootstrap as `enterApp`
  (profile → org → project → canvas, creating only what's missing) and returns the path to that
  canvas, `/p/<projectId>/c/<canvasId>`.
- The root hook (`src/hooks.server.ts`) now sends a logged-out visitor to `/login` and a
  logged-in one straight to their canvas — never to `/app`.
- `/app` itself is now a 308 permanent redirect to the same destination, so old bookmarks and
  emails keep working without any code pointing there on purpose.
- Login, the OAuth callback and the password-reset action redirect the same way.
- `/app/billing`, `/app/api-keys` and `/app/raster` are unaffected: they are real pages, not the
  deprecated dashboard, and keep working under `/app/...`.

## Why

`/app` was never rebuilt after the canvas shell landed — its dashboard UI was dead code kept
alive only by other routes still naming it as a redirect target. The production 404 was the
first visible symptom; the deeper problem was that "where does a logged-in user land" was
decided ad hoc, by string literal, in a dozen places instead of one function.
