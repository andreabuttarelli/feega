# Node data: last writer wins per path, deep

Before: `patchNodeData` refused (409) any write whose key had moved since
the client's base, the client reread and resent once, and a second clash
showed "Reload to see both edits". `params`/`filters` merged one level
only, so two people editing `params.size.w` and `params.size.h` collided.

Now (`node-patch.ts`):
- `MergeRule.Deep` replaces `OneLevel`: diff, merge and base follow
  `params`/`filters` down to the leaf. The conflict unit is a path
  (`params.size.h`), as in Figma's (object, property).
- A same-path race is last-writer-wins in server arrival order: no 409.
- The one exception is a list: replacing an array someone else changed
  would drop their items, so a moved list still clashes and the client
  rereads and resends (`writeWithRetry`). The rule is by value shape, not
  a table of key names: every array behaves the same.

Not done: moving the merge into one SQL statement. The optimistic
`version` loop stays; with clashes now rare it retries only on true
concurrent commits.
