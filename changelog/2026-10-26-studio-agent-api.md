# Photo studio batches over the API, CLI and MCP

A person prices and starts a Photo studio batch in the app; an agent could only follow one. `POST /api/v1/studio/quote` returns count, credits and a stateless `quoteId` (sha256 of the selection plus per-image price and count). `POST /api/v1/studio/start` requires that id, recomputes the quote, answers 409 when selection or price moved, passes the org credit gate, then calls `startBatch`. The quote summary moved out of the page action into `studio-quote.ts` so page and API share it (separate commit).

CLI `feega studio quote|start|status`, MCP `studio_quote`, `studio_start`, `studio_status`, parity rows for the three page actions. Batch page actions (run, more, cancel, retry, regenerate, approve, reject) now have `studio_*` MCP tools and `feega studio <action>` commands over `POST /api/v1/studio/{batchId}?action=`. Their bodies moved to `studio-actions.ts`, shared by the page and the API (separate commit). The studio endpoints now resolve the caller with `resolveOrgCaller`, so `feega_` API keys work; read-only keys are refused on start and actions with 403. Caller org comes from the key, or `?org=` for a JWT. `drain` stays ui-only.
