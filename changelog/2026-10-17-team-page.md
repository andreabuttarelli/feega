# Team page, invites, roles and editor seats

The only team UI was a project-settings page (404 in multi-tenant setups
without `hasManyTenants`) that invited as `member` by email and revoked.
No role changes, removal, leave, ownership transfer, link or limits.

Now `/app/team` (sidebar "Team") manages the active org. One service,
`team/team.ts`: `listTeam`, `runTeamOp` with `TeamOp` (invite,
resend_invite, revoke_invite, invite_link, disable_invite_link,
set_role, remove_member, leave, transfer_ownership). Every op maps to an
`OrgAction` in one table (`OP_ACTION`) checked with `can()`; refusals
are a `TeamRefusal` enum mapped to HTTP status in one table in the route.

Path: buttons in `routes/app/team/+page.svelte` -> `sendJson` ->
`POST /api/v1/orgs/[orgId]/team` -> `runTeamOp` -> repos
(`orgs_invites`, `orgs_members`, rpc `transfer_org_ownership`) + mail
(`team/invite-mail.ts`, the existing invite template).

Invite link: an `orgs_invites` row with `email = LINK_INVITE_EMAIL`,
role viewer, 365-day expiry, never marked accepted (`acceptInviteWith`
skips the email match for it). The raw token is shown once, like API
keys; reset deletes the row and mints a new one. Domain capture was
discarded for v1.

Seats (`team/seats.ts`): `SEAT_LIMITS` free = 3 editors, paid =
unlimited; editors = owner/admin/member plus pending editor invites;
viewers free. Checked on invite and on promotion to an editor role;
refusal `seat_limit` (402) carries `upgrade_path` (/app/credits).
Numbers are a proposal (FIGMA-TEAMS.md).

The old project-settings team page now links here; its `invite` and
`revokeInvite` actions are removed. CLI `feega team ...`, MCP
`list_team` and `team_op`.
