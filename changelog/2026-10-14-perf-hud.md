# Perf HUD on real devices

`?perf=1` (or `localStorage['feega:perf-hud'] = '1'`) mounts a fixed overlay on any page:
real rAF rate, worst-5% fps, p50/p95/max frame time, a frame-time histogram, long tasks and DOM
size (plus `.svelte-flow__node` count). `?perf=0` turns it off and clears the stored flag. The
component is lazy-imported: without the flag it is not in the page.

Why: the Playwright frame budget runs headless; ProMotion Macs and iPhones never got measured.

- Long tasks: `PerformanceObserver('longtask')` where supported (Chromium). WebKit has no
  `longtask` entry type, so there the HUD counts frames longer than 50 ms and says so.
- Safari caps `requestAnimationFrame` at 60 Hz by default on ProMotion displays; CSS/compositor
  animations and scrolling still run at 120 Hz. The HUD then reads 60: that is the setting, not
  the canvas. To see 120: Safari > Settings > Advanced > Feature Flags (macOS) or Settings >
  Apps > Safari > Advanced > Feature Flags (iOS), disable "Prefer Page Rendering Updates near
  60fps". Sources: WebKit bug 173434, whatwg/html#5025.
