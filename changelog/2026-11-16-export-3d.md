# Code export carries 3D model and shape layers

A frame with a `Model3D` or `Shape3D` layer exported to code with the note
"Model3D layers have no static HTML equivalent and were left out".

Now each becomes one `div` (same clip id across views, so breakpoint overrides
and layout rules apply like any box) holding a three.js canvas:

- React: React Three Fiber (`@react-three/fiber` 9, React 19 compatible), no
  drei: `useLoader(GLTFLoader)` is the only loading code drei would remove.
- HTML: plain three.js module over an import map (CDN, no build step).
- Svelte: plain three.js in an action. Threlte would add a dependency to
  replace ~30 lines the HTML target already has.

One table, `codegen/scene3d.ts`, turns doc properties into three.js numbers
(rig, lighting preset, geometry, surface, camera channels). Orbit, dolly, fov
and object rotation, keyframed or from start/end angle and easing, are
sampled once per frame with the canvas's own `sampleTrack`, so no easing code
ships. The three targets read the same data, and a test asserts the table
matches the constants in `hyperframes/three.ts`.

Pinned `three@0.181.2`, the version the canvas renders with.
Left out, with a note: the video's lighting look, the video camera on world
layers, Text3D, Logo3D, Device3D.

Rendered in Chromium against `composeHtml` (`scripts/export-3d/compare.ts`):
SSIM 1.0000 at 0, 2 and 4 s for HTML, React and Svelte.
The canvas paints a non-transparent backdrop over the whole frame, the export
over the layer box only.
